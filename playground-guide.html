Mettre Olive & Ember en démo sur WordPress Playground

Guide pas à pas — dépôt mouradlhousni/restaurant-demo, branche master, fichier blueprint.json.

Principe : rien n'est hébergé. Le visiteur ouvre un lien playground.wordpress.net, son navigateur télécharge blueprint.json depuis GitHub, puis installe WordPress (PHP en WebAssembly + SQLite), le plugin et le thème directement depuis le dépôt. Tout disparaît quand l'onglet est fermé.
1

Vérifier les prérequis

ÉlémentÉtat
Dépôt GitHub public (Playground ne peut pas lire un dépôt privé)OK
Assets JS/CSS compilés commités (plugins/oe-reservations/build/)OK
Plugin autonome sans vendor/ Composer (autoloader PSR-4 intégré)OK
OE_DEMO_MODE à true dans le blueprintOK
Branche locale synchronisée avec origin/masterOK à re-vérifier après chaque modif

Si tu modifies des blocs (JS dans src/), recompile avant de commiter, sinon Playground chargera l'ancien build/ :

npm run build
2

Pousser le code sur GitHub

Le blueprint installe le thème et le plugin depuis la branche master du dépôt distant : seul ce qui est poussé compte.

git status
git add -A
git commit -m "Prepare Playground demo"
git push origin master

Vérifie que le blueprint est bien accessible (doit afficher le JSON) :

raw.githubusercontent.com/…/master/blueprint.json

GitHub met en cache les fichiers raw environ 5 minutes : après un push, attends un peu ou teste dans une fenêtre privée.
3

Ouvrir la démo

Voici le lien public de la démo (déjà présent en haut du README.md) :

▶ Lancer la démo

Ce que fait le blueprint (≈ 30 à 60 s)

  1. Installe WordPress (dernière version) sur PHP 8.2.
  2. Définit OE_DEMO_MODE = true et OE_STATIC_BUILD = false dans wp-config.php.
  3. Installe et active le plugin oe-reservations depuis plugins/oe-reservations.
  4. Installe et active le thème olive-ember depuis themes/olive-ember.
  5. Active les permaliens /%postname%/.
  6. Lance wp oe seed --images=8 (plats, réglages, réservations de démo).
  7. Connecte l'utilisateur admin et ouvre la page d'accueil.

5

Tester en local avant de pousser (optionnel)

La CLI officielle lance le même blueprint sur ta machine (Node 20+) :

npx @wp-playground/cli@latest server --blueprint=./blueprint.json

Puis ouvre http://127.0.0.1:9400. Attention : le blueprint télécharge toujours le code depuis GitHub. Pour tester des modifications non poussées, monte les dossiers locaux à la place :

npx @wp-playground/cli@latest server --login \
  --mount=./plugins/oe-reservations:/wordpress/wp-content/plugins/oe-reservations \
  --mount=./themes/olive-ember:/wordpress/wp-content/themes/olive-ember

puis active plugin et thème, et lance wp oe seed depuis l'admin ou via une étape wp-cli.

6

Partager la démo

  • README : le lien « Try the live demo in WordPress Playground » est déjà en place.
  • Upwork : ajoute le lien dans le projet du portfolio, avec une capture et une phrase du type « Runs entirely in your browser — nothing is hosted, demo mode on. »
  • Lien direct vers la réservation : change "landingPage" dans blueprint.json (par ex. "/reservation/") si tu veux un lien qui ouvre directement le formulaire, ou crée un second blueprint.
  • Lien vers l'admin : "landingPage": "/wp-admin/admin.php?page=…" pour montrer directement l'écran Reservations.
  • Ajoute le lien Playground dans la version statique (dist/) — le bloc « Reservation Form » pointe déjà vers « Try the booking flow live ».
7

Dépannage

SymptômeCause probable / solution
Erreur au chargement du blueprintDépôt privé, mauvaise branche (master vs main) ou JSON invalide. Valide le fichier sur le Blueprint builder.
Ancienne version affichée après un pushCache raw.githubusercontent.com (~5 min) ou cache du navigateur : fenêtre privée.
Échec de l'étape installPlugin / installThemeChemin path incorrect dans le blueprint, ou dossier renommé dans le dépôt.
Blocs vides ou cassésbuild/ non recompilé / non commité : npm run build puis push.
Seed trop long ou timeoutRéduis le nombre d'images : wp oe seed --images=4 (objectif < 60 s).
Images absentesFichiers d'images non commités ou trop lourds ; vérifie qu'ils sont bien suivis par Git.
Page blanche / erreur PHPAjoute temporairement "WP_DEBUG": true dans l'étape defineWpConfigConsts et relance.
